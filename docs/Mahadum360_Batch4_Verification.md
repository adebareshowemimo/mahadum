## Operation and release handover

1. Install the locked Composer dependencies and apply all three `2026_10_07_06*` migrations before serving the updated API. Build/deploy the SPA including `notification-sw.js` at the web origin root.
2. Verify `FRONTEND_URL` points to the SPA, configure a real email transport and run a queue worker. School invitations expire after seven days; revoke/resend when necessary. “Queued” means queued, not delivered.
3. Run the Laravel scheduler. `family:send-alerts` is scheduled every 15 minutes without overlap. Inactivity uses the latest lesson-progress update, quiz-attempt update, existing speaking submission or profile creation. Low balance refers to the family wallet, not child or pool balances. Alert deduplication is per condition episode; no automatic rewards or pool releases occur. Queue-dispatch failures reset the claimed episode for retry. Coin-movement endpoints keep successful balance responses if notification dispatch fails, avoiding duplicate-transfer retries; queued provider jobs use the queue’s retry/failed-job handling.
4. For browser push, configure a deployment-specific `WEB_PUSH_PUBLIC_KEY`, `WEB_PUSH_PRIVATE_KEY` and HTTPS/mailto `WEB_PUSH_SUBJECT`, then enable `MESSAGING_LIVE`. PHP needs cURL, mbstring, OpenSSL with EC support and a valid OpenSSL configuration; the XAMPP test-key generation check needed `OPENSSL_CONF` pointing to its existing `php/extras/ssl/openssl.cnf`. Tests use a public test-only key pair, never deployment keys. Keep real private keys out of Git.
5. Use HTTPS (localhost is permitted by browsers for development). Each eligible, verified account must opt in on its browser. Notification details remain behind login. Browser/provider support differs; unsupported/denied/unconfigured states are visible. No real subscription permission was requested during this verification.
