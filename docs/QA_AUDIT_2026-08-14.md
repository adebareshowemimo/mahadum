# MAHADUM.360 QA and UI/UX audit — 14 August 2026

## Scope and evidence

This audit covers the Laravel API, authenticated React SPA, shared UI primitives, route/RBAC boundaries, class/course/learner flows, responsive implementation, and production configuration that can be verified without making real payments or sending messages to third parties.

Evidence used:

- frontend TypeScript production build and Vitest/axe suite;
- focused Laravel feature tests for teacher, school-admin, class, course, invitation, tenant and assignment behavior;
- PHPStan level 5 and Pint;
- source inspection of 90 page modules, navigation/route guards and shared controls;
- Impeccable static UI detector over `web/src`;
- production deployment, migration, route and queue-worker checks.

External payment, telco and real outbound-email delivery require provisioned production providers and cannot be truthfully certified from application code alone.

## Anti-pattern verdict

The application does not look like a generic generated template: it has a real token system, culturally specific product language, a consistent shell and meaningful role-aware flows. The main trust problem is interaction architecture rather than decoration. Too many multi-step tasks open in temporary dialogs, which makes navigation, mobile use, bookmarking and recovery harder than necessary.

## Findings and status

### P0 — Production outbound email is not delivering

- **Location:** production environment (`MAIL_MAILER=log`)
- **Impact:** class invitations and other transactional messages are written to logs rather than delivered to inboxes.
- **Status:** **Blocked by infrastructure.** No SMTP/API credentials, verified sending domain or Azure email resource is provisioned. Application invitation logic and queueing are implemented and tested. A real provider must be configured before delivery can be certified.

### P1 — Class management was a task-heavy modal

- **Location:** former `ClassesPage` class-detail modal
- **Impact:** teachers lost context, could not bookmark a class section, and had little room for roster, course and analytics work.
- **Status:** **Fixed.** `/classes/:classId` is now a dedicated workspace with learners, courses, assignments and analytics.

### P1 — Assigned courses could disappear

- **Location:** `ClassCourseController::index`
- **Impact:** an assigned course vanished from the class UI if its publication status changed, even though the assignment still existed.
- **Status:** **Fixed and regression-tested.** Assigned courses remain visible and show “No longer published” when appropriate.

### P1 — School-admin class permissions disagreed with frontend routing

- **Location:** class routes in `App.tsx`
- **Impact:** school administrators could manage classes through the API and see class cards, but the SPA redirected them away from class details.
- **Status:** **Fixed.** Teacher and school-admin users can open class workspaces; teacher-only assignment creation/grading remains restricted.

### P1 — Dialog keyboard/focus behavior was incomplete

- **Location:** shared `Modal`
- **Impact:** keyboard and screen-reader users could move behind an open dialog, lose their place after closing, and scroll background content.
- **WCAG:** 2.1.1 Keyboard, 2.4.3 Focus Order.
- **Status:** **Fixed and tested.** Focus enters and stays within the dialog, Escape closes, focus is restored, body scrolling is locked, and dialog content scrolls within the viewport.

### P1 — Form errors and hints were not associated with controls

- **Location:** shared `Input` and `Textarea`
- **Impact:** screen readers announced an invalid control without reliably announcing the reason or guidance.
- **WCAG:** 1.3.1 Info and Relationships, 3.3.1 Error Identification.
- **Status:** **Fixed.** `aria-describedby` and live error semantics are generated consistently.

### P2 — Unknown URLs silently redirected to the marketing home page

- **Location:** wildcard route in `App.tsx`
- **Impact:** users could not tell whether a link was invalid, moved or forbidden.
- **Status:** **Fixed.** A clear not-found page now returns users to the appropriate signed-in or public destination.

### P2 — Narrow-screen forms forced two columns

- **Location:** assignments, audit detail, reports, lesson insights, promo codes and chore forms.
- **Impact:** labels and controls became cramped on small phones or at high zoom.
- **Status:** **Fixed for confirmed task forms.** They now stack by default and become two columns at the small breakpoint.

### P2 — Product buttons used display typography

- **Location:** shared button/link-button class vocabulary.
- **Impact:** decorative letterforms in dense task controls reduce familiarity and scan speed.
- **Status:** **Fixed.** Standard controls now inherit the product sans family; expressive button styles remain available in dedicated marketing components.

### P2 — Task-heavy modal usage remains widespread

- **Location:** 45 modal call sites across 90 page modules.
- **Impact:** complex assignment review, user administration, email editing and course authoring can be difficult to bookmark, recover or use on mobile.
- **Status:** **Open follow-up.** Creation, confirmation and short decision dialogs are appropriate. Rich detail/editor dialogs should be migrated page-by-page, starting with assignment grading, user detail, campaign/template editing and lesson authoring.

## Positive findings

- Row-level tenancy and policy checks are separated and extensively tested.
- Navigation is role-filtered and the adaptive shell supports mobile and desktop.
- Shared controls already provide visible focus treatment and 44px targets.
- Public/auth surfaces covered by axe have no detected WCAG A/AA violations.
- SPA pages are route-split; images generally lazy-load and provide fallbacks.
- Learning access is not paywalled, and wallet/coin mutations use server-side ledgers and approval rules.
- Empty, loading and error states exist across most shipped pages instead of rendering blank content.
