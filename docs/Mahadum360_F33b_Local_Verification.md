## Finding and repair

F33a repaired the existing backend partial-update validator so teacher_user_id alone can update a class. It did not add any controls to ClassPage: /classes/:classId had neither an Assign teacher button nor an Edit class button. A separate dashboard-only selector also hides when its teacher list is empty, so visiting the class workspace gives no route to the existing operation. This candidate adds those two controls to the class workspace, with prefilled name/level editing, active-school teacher selection, saving/loading states and visible field/general errors. Teacher assignment sends only teacher_user_id; name/level editing does not send a teacher or roster field. Success invalidates the existing class query keys so the header/stat refresh.

Class detail now includes organization_id, teacher_user_id and capabilities derived from the existing SchoolClassPolicy and controller restriction. The UI follows those decisions: an authorized school admin may edit/assign; a teacher may edit their own class but cannot reassign its teacher; another class teacher/read-only viewer gets no management controls. API policy, role grants, tenant middleware, assignment membership validation and teacher self-assignment restrictions are unchanged. Teachers are queried only when the authorized assignment dialog opens, against that class's organization.

The mixed-role no-school case also reproduces safely: adding a global Teacher role to a parent does not create an active school membership. Existing backend tests require 403 for classes/create in that situation. The UI previously made that forbidden request and promised a refresh would fix it. /classes now avoids an unscoped request when no school is available and explains that an active school link is needed. A 403 in a selected school receives actionable membership guidance rather than the refresh loop. A linked Parent + Teacher account continues to request its own classes with mine=true. No account is auto-linked and no permission is added.
