Adebare explicitly authorized commit/push of this tested roster batch on 6 October ("yes" to the commit/push question). Exact commit and remote verification are reported in the release handoff. This authorization does not imply local manual acceptance. Production deployment and roster Deborah QA remain pending. The parent owns emails and Adebare owns server deployment.

The downloadable template now uses Firstname,Lastname,Email,Level. Email is optional: blank retains the existing school-managed profile creation flow. A supplied learner login matches one existing learner profile already linked to the same school, ignoring email case and surrounding CSV spaces. A matched row preserves its existing profile name, level, login, family and organization, creates no duplicate profile and fills no additional seat. Class enrollment, when supplied through the existing API, remains restricted to a class in the same school and uses the existing enrollment service.

Unknown, foreign-school and ambiguous emails produce row errors. Import does not create a login, assign roles, move a learner between schools, or infer a child from a parent's email. New learners with logins use the existing class invitation/self-acceptance flow. Any requested automatic parent linking or new-account creation requires a separate ownership/product decision; it is not claimed by this fix.

CSV rows are validated before profile, enrollment or seat writes. Names are required and at most 255 characters; email must be valid when supplied; Level is at most 100 characters. A foreign class fails before creating a profile. Valid rows still import when other CSV rows fail. Error numbers count CSV records including the header (row 2 is the first student); a quoted multiline record is one record. Headerless rows start at 1. Existing three-column files, display_name headers, reordered/case-insensitive headers and UTF-8 BOM files remain supported. Inline JSON retains its existing request-level validation; a malformed JSON field can reject the whole request with 422. Do not generalize partial CSV import behavior to every malformed JSON request.
