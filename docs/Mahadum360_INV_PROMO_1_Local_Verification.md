The existing Invoice::breakdownLines method normalizes legacy fee labels. It also normalized promo descriptions containing registration, or both student and school. For example, Promo code: REG50 (School registration) became Registration Fees with a negative amount. The invoice UI therefore lost the promo marker and showed its Apply control again; the existing controller's no-stacking check could not recognize the first discount and accepted a different second code. This was reproduced with no real invoice, redemption, payment or customer mutation.

The fix excludes descriptions starting with Promo code: from fee-label normalization. Their original label and signed amount survive, while the existing canonical fee normalization still applies. No discount percentage, target, VAT calculation, redemption limit, payment provider, checkout behavior or new commercial rule was introduced. The existing invoice no-stacking rule is retained and now recognizes the applied code.
